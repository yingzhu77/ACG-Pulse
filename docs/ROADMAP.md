本轮以 `c58ef2d` 为基线，优先串通「采集 → 事件 → 今日精选 → 原文 → 往期」。参考 [AIHOT](https://aihot.news/) 的精选、全量、热点和日报分入口，以及 [AIHOT 开源仓库](https://github.com/KKKKhazix/AIHOT) 的按事件组织思路（MIT；未复制代码、提示词或品牌）。继续使用现有采集队列，不新增筛选模型调用或信源。

- **事件**：近两周按作品与明确标题标识保守匹配，精确出处优先，多解保留独立条目。根据同一版本的官方阶段变化识别实质进展。浏览器旧收藏只迁移可确认的映射；歧义保留原收藏并提示。普通容量清理限制热数据，过限事件最多保留 3 条缩短的出处记录（首发现、最早原文、最后进展，可重合），以免引用失效；历史事件元数据和刊期随新事件累积，并非固定总库上限。
- **精选**：首次非空成功抓取建立基线，不参加今日精选。无可靠原文时间、比原文晚发现超过 48 小时或原文时间明显超前的条目留在全量。可用的迟到报道按发现日（或首次具备分析的可用日）参加下一未出刊期，保留原文时间。日报和实时精选共用同一套规则，每期上限 8 条。
- **日报**：上海时间每天 00:10 尝试出上一期，采集任务完成后也会重试最近 3 个已结束日期；更早的失败期可由管理 API 补刊。快照不因重跑或原文更新而变，撤回或更正覆盖公开显示。无合格内容与采集/分析不完整分开处理；有可用内容时保留展示并标明覆盖不全。
- **迁移**：先备份再在数据库副本验证 `cd server && npm run db:deploy && npm run db:generate`。新增列和表，不替换 SQLite，不重算旧分析；既有来源从其最早保留条目补入基线标记。首次读取事件/精选或触发超额清理时给现存条目建立事件归属。复跑不重复建事件。快照撤回由迁移里的触发器保护，不使用 `db:push` 代替此迁移。如需回滚，停用新实例后恢复备份，不在现有数据库手工删列。
- **本地验收**：见 [README 的隔离样本](../README.md#先用隔离样本体验) 和 [接口契约](API_CONTRACTS.md)。合成样本覆盖同事件转载、实质进展、独立事件、回填、未知时间、分析失败和来源降级；不把样本预期当作真实内容准确率。

### 第二轮：修复漏报与误选，完成阅读体验验收

- **重复阶段可以有新事实**：热修、补偿、延期、更正的阶段仍用于归组。同阶段只有官方原文中可识别的新增修复对象、发放数值、改期或更正事实才算进展；相同正文、格式变化、仅换链接和重复任务不新增进展。
- **PV 形式不阻断版本归组**：官方版本前瞻与上线公告在作品、版本号及明确版本名相符时可归为一个事件；角色 PV、二创、冲突名称和不同版本仍独立。
- **精选不推翻有效分析**：低价值分析不会被标题关键词抬升。缺少有效分析时，只兜底官方明确运营通知；不编造摘要、影响或模型状态。最近采集尝试与最近成功分别记时，延迟可和失败并存；超过 60 分钟的缓存不因刚刚失败的重试变得新鲜。日报快照不随当前状态重算。
- **阅读页**：精选、详情和日报使用窄版阅读区；收录时间与详细采集信息折叠，全量/洞察保留工作台布局。作品选择保存在当前浏览器，失效时回到全部，事件返回保留列表位置。管理员与原有导航不移除。

#### 存量事件修正（可选，默认仅预览）

先按现有备份流程取得**已迁移的隔离 SQLite 副本**。应用启动或正常更新不会自动执行修正。两个日期为上海时间，结束日不含当日：

```bash
cd server
npm run repair:events -- --db /absolute/path/to/copy.db --since 2026-11-10 --until 2026-11-20
# 确认预览后，仍在同一隔离副本上执行；替换 FINGERPRINT 为实际值：
npm run repair:events -- --db /absolute/path/to/copy.db --since 2026-11-10 --until 2026-11-20 --apply FINGERPRINT
```

必要时增加 `--game`。范围至多 30 天、400 个候选事件、2,000 篇文章，超限缩小范围。命令先核对 SQLite 文件与 Prisma 真正打开的路径；应用时在事务中重算预览，指纹不同就退出。只补证据充分的进展标记或一对一的前瞻／上线归组，保留原文、较早事件 ID 与旧链接别名。人工拆分、歧义、涉及归档的复杂历史及已有刊期引用的待合并事件不自动修正；已出刊内容需要改动时走已有更正/撤回流程。应用后复跑预览应无同一批更改。不访问生产数据库，不重跑模型。

## 边界与操作约束

- 不使用 B站直连 fallback 绕过 RSSHub 故障；单轮 503 不等于固定源故障。
- 真实 AI 调用、付费采集源和公开部署都需要单独授权；验收默认使用隔离 SQLite、空 AI Key 或受控 Provider。
- 原始观察 JSON 和隔离库保留在本地 `tmp/upstream-observation/`（已忽略）；仓库只提交脱敏摘要和可复用脚本。
- 多轮成功仍不代表长期稳定；报告必须注明执行时间、失败 UID 和复测状态。
